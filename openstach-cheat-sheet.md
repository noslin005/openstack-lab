## Undo `init-runonce`

`init-runonce` creates a demo router, two networks, a CirrOS image, default flavors, a keypair and security group rules. Delete anything built on top of them first (instances, floating IPs, ports), or the network and router deletes will fail.

```bash
# 0. Check for leftovers that would block the deletes
openstack server list --all-projects
openstack floating ip list
openstack port list --network demo-net
# openstack floating ip delete <ip-or-id>
# openstack server delete <name-or-id>

# 1. Clear the external gateway from the router
openstack router unset --external-gateway demo-router

# 2. Detach the demo subnet from the router
openstack router remove subnet demo-router demo-subnet

# 3. Delete the router
openstack router delete demo-router

# 4. Delete the networks (this also removes their subnets)
openstack network delete demo-net
openstack network delete public1
```

Optional extra cleanup (skip anything you want to keep):

```bash
openstack image delete cirros
openstack keypair delete mykey
openstack security group rule list default     # then delete the demo rules by ID
# openstack security group rule delete <rule-id>
```

> If you re-create the default flavors yourself, see [Flavors](#flavors).

## Neutron networks and routers

### Private (tenant) network

```bash
openstack network create mgmt-net
openstack subnet create mgmt-subnet \
  --network mgmt-net \
  --ip-version 4 \
  --subnet-range 10.128.0.0/16 \
  --gateway 10.128.0.1 \
  --dns-nameserver 1.1.1.1
```

### Public (external) network, flat

`physnet1` must match a mapping in `bridge_mappings` (here `physnet1:br-ex`) and in `flat_networks` of `ml2_conf.ini`.

```bash
openstack network create external-net \
  --external \
  --provider-physical-network physnet1 \
  --provider-network-type flat

openstack subnet create external-subnet \
  --network external-net \
  --no-dhcp \
  --ip-version 4 \
  --subnet-range 10.7.0.0/24 \
  --allocation-pool start=10.7.0.119,end=10.7.0.239 \
  --gateway 10.7.0.1 \
  --dns-nameserver 10.7.0.1
```

### Router

```bash
openstack router create core-router

# Attach the internal network
openstack router add subnet core-router mgmt-subnet

# Attach the external network (SNAT enabled by default)
openstack router set core-router --external-gateway external-net
```

Verify:

```bash
openstack router show core-router -c external_gateway_info -c interfaces_info
openstack network list
openstack subnet list
```

## OVS bridges and packet flow

How a default Kolla deployment (OVS + VXLAN tenant networks, non-DVR) wires things together. Bridge names match your config (`bridge_mappings = physnet1:br-ex`).

- **br-int**: integration bridge on every node. VM ports (`tap…`), DHCP ports and router ports (`qr-…`, `qg-…`) all plug in here. Each Neutron network gets a **local VLAN tag**, which only has meaning on that host.
- **br-tun**: tunnel bridge on every node. Translates local VLAN to VXLAN VNI and back, and holds the `vxlan-<peer>` ports.
- **br-ex**: external bridge on the **network node only** (compute nodes have none unless you use DVR). It holds the physical NIC.
- **Patch ports** are virtual cables between bridges: `br-int:patch-tun` <-> `br-tun:patch-int`, and `br-int:int-br-ex` <-> `br-ex:phy-br-ex`.

VM1 and VM3 are on net-A, VM2 and VM4 on net-B. `qr-1` is the router port on net-A, `qr-2` the router port on net-B, and `qg` the gateway port on the external network.

```text
+---------------------------------------+    +---------------------------------------+
| COMPUTE NODE 1   (VM1, VM2)           |    | COMPUTE NODE 2   (VM3, VM4)           |
|                                       |    |                                       |
|       +-----+           +-----+       |    |       +-----+           +-----+       |
|       | VM1 |           | VM2 |       |    |       | VM3 |           | VM4 |       |
|       +-----+           +-----+       |    |       +-----+           +-----+       |
|          |tap1             |tap2      |    |          |tap3             |tap4      |
|  +-------+-----------------+-------+  |    |  +-------+-----------------+-------+  |
|  | br-int  (OVS firewall driver)   |  |    |  | br-int  (OVS firewall driver)   |  |
|  | local VLAN tag per network      |  |    |  | local VLAN tag per network      |  |
|  +----------------+----------------+  |    |  +----------------+----------------+  |
|                   | br-int:patch-tun  |    |                   | br-int:patch-tun  |
|                   | br-tun:patch-int  |    |                   | br-tun:patch-int  |
|  +----------------+----------------+  |    |  +----------------+----------------+  |
|  | br-tun                          |  |    |  | br-tun                          |  |
|  | local VLAN <-> VXLAN VNI        |  |    |  | local VLAN <-> VXLAN VNI        |  |
|  +----------------+----------------+  |    |  +----------------+----------------+  |
|                   | vxlan-<peer>      |    |                   | vxlan-<peer>      |
+-------------------+-------------------+    +-------------------+-------------------+
                    |                                            |
====================+=========+=== VXLAN, UDP 4789 (local_ip) ===+====================
                              | vxlan-<peer>
+-----------------------------+------------------------------------------------------+
| NETWORK NODE                                                                       |
|                                                                                    |
|            +----------------+----------------+                                     |
|            | br-tun                          |                                     |
|            | VXLAN VNI <-> local VLAN        |                                     |
|            +----------------+----------------+                                     |
|                             | br-tun:patch-int                                     |
|                             | br-int:patch-tun                                     |
|            +----------------+----------------+      +---------------------------+  |
|            | br-int                          +-tap--+ qdhcp-<net-id>            |  |
|            | local VLAN tag per network      |      | dnsmasq + metadata proxy  |  |
|            | (tag is local to this host)     |      +---------------------------+  |
|            |                                 |      +---------------------------+  |
|            |                                 +-qr-1-+ qrouter-<router-id>       |  |
|            |                                 +-qr-2-+ L3 agent: routes subnets  |  |
|            |                                 +--qg--+ SNAT + floating-IP NAT    |  |
|            |                                 |      | iptables nat table        |  |
|            +----------------+----------------+      +---------------------------+  |
|                             | br-int:int-br-ex                                     |
|                             | br-ex:phy-br-ex                                      |
|            +----------------+----------------+                                     |
|            | br-ex  (physnet1)               |                                     |
|            | flat: untagged / vlan: tagged   |                                     |
|            +----------------+----------------+                                     |
|                             | physical NIC (e.g. eth1)                             |
+-----------------------------+------------------------------------------------------+
                              |
==============================+===== EXTERNAL NETWORK  10.7.0.0/24  gw 10.7.0.1 ======
```

### Packet walks

**A. VM1 `->` VM3 (same network, different compute nodes)**

1. VM1 `eth0` `->` `tap1` on br-int (compute 1). br-int tags the frame with net-A's local VLAN and applies egress security-group flows.
2. Frame goes out `patch-tun` and into br-tun via `patch-int`.
3. br-tun maps local VLAN `->` VNI, removes the tag and sends it out the `vxlan-<peer>` port for compute 2. With `l2_population` this is a unicast flow, not a flood.
4. The underlay carries it as UDP/4789 between the two `local_ip` addresses.
5. br-tun on compute 2 maps VNI `->` local VLAN `->` `patch-int` `->` br-int. Ingress security-group rules are applied, the tag is removed, and the frame is delivered to `tap3` `->` VM3.

**B. VM1 (net-A) `->` VM4 (net-B), routed**

1. Steps 1 to 4 from A, but the destination MAC is the router's `qr-1`, so the tunnel goes to the **network node**.
2. Network node: br-tun `->` `patch-int` `->` br-int `->` `qr-1` inside the `qrouter-…` namespace.
3. The router forwards the packet out `qr-2` back into br-int (net-B's local VLAN) `->` br-tun `->` VXLAN (net-B's VNI) `->` compute 2 `->` br-int `->` `tap4` `->` VM4.

Without DVR, all routed traffic hairpins through the network node, even between VMs on the same compute node.

**C. VM1 `->` internet (default SNAT, no floating IP)**

1. VM1 `->` br-int `->` br-tun `->` VXLAN `->` network node br-tun `->` br-int `->` `qr-1` in the router namespace.
2. The router sends the packet out `qg` and SNATs the source to the router's external gateway IP.
3. `qg` is a port on **br-int**, so the packet crosses `int-br-ex` `->` `phy-br-ex` `->` br-ex `->` physical NIC `->` external gateway (`10.7.0.1`).
4. The reply comes back the same way. conntrack reverses the NAT, the router sends it out `qr-1`, and it returns over VXLAN to VM1.

**D. With a floating IP**

- **Outbound**: same as C, but the router does a 1:1 SNAT to the floating IP instead of the gateway IP.
- **Inbound**: external host `->` NIC `->` br-ex `->` `phy-br-ex` `->` `int-br-ex` `->` br-int `->` `qg`. The router answers ARP for the floating IP, DNATs to the fixed IP, and routes out `qr-1` `->` br-int `->` br-tun `->` VXLAN `->` compute node `->` br-int `->` tap `->` VM.

**E. DHCP and metadata**

`qdhcp-<net-id>` runs dnsmasq on the network node and plugs into br-int with a `tap` port. VM DHCP requests ride the same br-int `->` br-tun `->` VXLAN path as any other broadcast.

### Notes

- **Firewall driver**: with `firewall_driver = openvswitch` the VM `tap` plugs straight into br-int, as drawn. With `iptables_hybrid` each VM goes `tap` `->` `qbr` (Linux bridge with iptables) `->` `qvb`/`qvo` veth pair `->` br-int.
- **Flat external network**: br-ex passes frames untagged.
- **VLAN provider network** (e.g. VLAN 19): OVS flows on `int-br-ex` / `phy-br-ex` translate the local VLAN <-> provider VLAN 19, and the frame leaves the NIC tagged.
- **DVR**: compute nodes also get a br-ex plus fip/qrouter namespaces, so floating-IP and east-west traffic skip the network node.
- **VNI** is the network's segmentation ID: `openstack network show <net> -c provider:segmentation_id`.
- **Port names**: `tap`, `qr-` and `qg-` devices carry the first 11 characters of the Neutron port UUID.

### Inspect it live

```bash
# Bridges, ports and patch/vxlan links (any node)
podman exec openvswitch_vswitchd ovs-vsctl show
podman exec openvswitch_vswitchd ovs-vsctl list-ports br-int
podman exec openvswitch_vswitchd ovs-vsctl list-ports br-tun

# Flows (OpenFlow13 is needed for OVS-agent flows)
podman exec openvswitch_vswitchd ovs-ofctl -O OpenFlow13 dump-flows br-tun
podman exec openvswitch_vswitchd ovs-ofctl -O OpenFlow13 dump-flows br-int

# Trace what OVS would do with a packet (replace the in_port and MACs/IPs)
podman exec openvswitch_vswitchd ovs-appctl ofproto/trace br-int \
  in_port=<tap-ofport>,tcp,dl_src=<vm-mac>,dl_dst=<gw-mac>,nw_src=<vm-ip>,nw_dst=8.8.8.8

# Check switch forwarding database (MAC)
podman exec openvswitch_vswitchd ovs-appctl fdb/show br-int

# Router and DHCP namespaces (network node)
podman exec neutron_l3_agent ip netns list
podman exec neutron_l3_agent ip netns exec qrouter-<router-id> ip addr
podman exec neutron_l3_agent ip netns exec qrouter-<router-id> iptables -t nat -S
podman exec neutron_dhcp_agent ip netns list
```

## Switch the firewall driver to Open vSwitch

Use the native OVS firewall driver instead of `iptables_hybrid`. It avoids the extra Linux bridge per VM port.

**1. Check the current config (network and compute nodes)**

```bash
podman exec neutron_openvswitch_agent \
  grep -E '^\s*(firewall_driver|trunk_enabled)' /etc/neutron/plugins/ml2/openvswitch_agent.ini
```

Full file for reference:

```ini
[agent]
tunnel_types = vxlan
l2_population = true
arp_responder = true

[securitygroup]
firewall_driver = neutron.agent.linux.iptables_firewall.OVSHybridIptablesFirewallDriver

[ovs]
bridge_mappings = physnet1:br-ex
datapath_type = system
ovsdb_connection = tcp:127.0.0.1:6640
ovsdb_timeout = 10
local_ip = 10.7.0.11

[OVS]
trunk_enabled = True
```

**2. Create the override (deploy host)**

Kolla merges files from `/etc/kolla/config/neutron/` into the generated config. `>` overwrites an existing file, so use `>>` or edit it if you already have overrides.

```bash
mkdir -p /etc/kolla/config/neutron
cat <<EOF > /etc/kolla/config/neutron/openvswitch_agent.ini
[securitygroup]
firewall_driver = openvswitch

[OVS]
trunk_enabled = True
EOF
```

Also uncoment and set `enable_neutron_trunk: true` in `/etc/kolla/globals.yml`

**3. Apply**

```bash
kolla-ansible reconfigure -t neutron -i $INV
```

**4. Verify**

```bash
openstack network agent list          # all agents should be :-) / UP
```

> Existing instances keep their old plumbing until their ports are re-plugged. Hard-reboot them to pick up the new driver: `openstack server reboot --hard <server>`.

## VLAN provider networks

### Check the current ML2 config (controller)

```bash
podman exec neutron_server cat /etc/neutron/plugins/ml2/ml2_conf.ini
```

```ini
[ml2]
type_drivers = flat,vlan,vxlan
tenant_network_types = vxlan
mechanism_drivers = openvswitch,l2population
extension_drivers = port_security

[ml2_type_vlan]
network_vlan_ranges =

[ml2_type_flat]
flat_networks = physnet1

[ml2_type_vxlan]
vni_ranges = 1:1000
```

An empty `network_vlan_ranges` means VLAN networks cannot be created on any physnet.

### Add a VLAN range (deploy host)

Format is `physnet:min:max`.

```bash
mkdir -p /etc/kolla/config/neutron
cat <<EOF > /etc/kolla/config/neutron/ml2_conf.ini
[ml2_type_vlan]
network_vlan_ranges = physnet1:2:20
EOF

kolla-ansible reconfigure -t neutron -i $INV
```

### Create the VLAN network

```bash
# --external makes it usable as a router gateway / floating IP pool.
# Drop --external and add --share for a plain shared provider network.
openstack network create public-vlan-network \
  --external \
  --provider-network-type vlan \
  --provider-physical-network physnet1 \
  --provider-segment 19

openstack subnet create public-vlan-subnet \
  --network public-vlan-network \
  --no-dhcp \
  --ip-version 4 \
  --subnet-range 10.19.0.0/24 \
  --allocation-pool start=10.19.0.50,end=10.19.0.200 \
  --gateway 10.19.0.1
```

> The physical switch port behind `br-ex` must trunk (tag) VLAN 19, or traffic will not leave the host.

### Common properties

| Property              | Values / Notes                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `os_type`             | `linux` or `windows`. Drives libvirt behaviour (swap partition format, hostname length, Hyper-V enlightenments)                                |

| `architecture`        | `x86_64`, `aarch64`, `i686`                                                                                                                    |
| `hw_machine_type`     | e.g. `pc`, `q35`, `virt`, `hyperv-gen1`, `hyperv-gen2`                                                                                         |
| `hw_firmware_type`    | `bios` or `uefi`                                                                                                                               |
| `hw_disk_bus`         | `virtio`, `scsi`, `ide`, `sata`                                                                                                                |
| `hw_vif_model`        | `virtio`, `e1000`, `e1000e`, `rtl8139`                                                                                                         |
| `hw_qemu_guest_agent` | `yes` exposes the guest-agent channel (needs `qemu-guest-agent` inside the image)                                                              |

## Keypairs and security groups

```bash
# Import an existing public key
openstack keypair create mykey --public-key ~/.ssh/id_ed25519.pub

# Or let OpenStack generate one (save the private key!)
openstack keypair create mykey > mykey.pem && chmod 600 mykey.pem

# List Security Group
openstack security group list

# Delete all rules in the default group
openstack security group rule list default -c ID -f value|xargs -i openstack security group rule delete {}

# Allow ping and SSH in the default group
openstack security group rule create default --protocol icmp --ingress
openstack security group rule create default --protocol tcp --dst-port 22 --ingress
# Or allow only specific IPs
openstack security group rule create default --protocol tcp --dst-port 22 --remote-ip 10.7.0.0/24 --ingress  --description 'Allow SSH from 10.7.0.0/24'
openstack security group rule create default --protocol icmp --remote-ip 0.0.0.0/0 --ingress --description 'Allow ICMP ping from anywhere'
```

## Troubleshooting Neutron

Every check below tests one hop of the path drawn in [OVS bridges and packet flow](#ovs-bridges-and-packet-flow). Work from the VM outward and stop at the first hop where packets disappear.

Handy aliases for Kolla (OVS tools live in the `openvswitch_vswitchd` container; use `docker` instead of `podman` if that is your engine):

```bash
alias ovs-vsctl='podman exec openvswitch_vswitchd ovs-vsctl'
alias ovs-ofctl='podman exec openvswitch_vswitchd ovs-ofctl -O OpenFlow13'
alias ovs-appctl='podman exec openvswitch_vswitchd ovs-appctl'
```

> Don't add `-t` (as in `exec -it`) when piping output. A TTY adds `\r` characters that corrupt `grep`, `gzip` and `base64`. Plain `exec` or `exec -i` is enough for non-interactive commands.

### Bridges and patch ports

| Bridge   | Present on                     | Purpose                                                                                               |
| -------- | ------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `br-int` | every compute and network node | Integration bridge: VM ports, DHCP and router ports, local VLAN tag per network, security-group flows |
| `br-tun` | every compute and network node | Tunnel bridge: VXLAN ports to every other node, translates local VLAN <-> VNI                         |
| `br-ex`  | network node only (unless DVR) | External bridge: holds the physical NIC (`eth2g` in the example below)                                |

Bridges are joined by **patch port pairs**. Each end has the other's name in `options:peer`:

| Pair                                          | Joins                 | Used for                                                           |
| --------------------------------------------- | --------------------- | ------------------------------------------------------------------ |
| `patch-tun` (br-int) <-> `patch-int` (br-tun) | `br-int` <-> `br-tun` | VM traffic to and from other hosts (same network, different nodes) |
| `int-br-ex` (br-int) <-> `phy-br-ex` (br-ex)  | `br-int` <-> `br-ex`  | Router gateway (`qg-`) traffic to and from the physical network    |

`br-ex` is connected to **`br-int`**, not to `br-tun`. External traffic never goes through the tunnel bridge on the network node. The router's `qg-` port is itself a port on `br-int`.

Port names carry the **first 11 characters of the Neutron port UUID** after the prefix: `tap6f70784c-f7`, `qr-6913bf48-bb`, `qg-992305b0-97`.

| Prefix              | What it is                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `tapXXXX` (compute) | VM interface created by libvirt (no `type:` shown in `ovs-vsctl show`)                          |
| `tapXXXX` (network) | DHCP port, an OVS `internal` port moved into the `qdhcp-` namespace                             |
| `qr-XXXX`           | Router interface on a tenant subnet (gateway IP), inside `qrouter-`                             |
| `qg-XXXX`           | Router gateway on the external network (and floating IPs), inside `qrouter-`                    |
| `qvoXXXX`           | Only with `iptables_hybrid`: veth end on `br-int` (the `qbr` bridge sits between it and the VM) |

```text
            Interface patch-int
                type: patch
                options: {peer=patch-tun}
```

What to look for:

- **`Manager` / `Controller` `is_connected: true`**: the OVS agent drives each bridge as an OpenFlow controller on `127.0.0.1:6633`. `false` means the agent is down or hung, and flows are no longer being managed.
- **`fail_mode: secure`** on `br-int` and `br-tun`: with no flows installed, all traffic is dropped. After an OVS restart, instances stay cut off until the agent reprograms the flows. `br-ex` is `standalone`, so it behaves as a normal learning switch even without the agent.
- **`tag: N`** is the **local VLAN**, specific to this host. Here net `mgmt-net` is tag 1 (`qr-`, DHCP `tap`) and `external-net` is tag 2 (`qg-`). Another node may use different numbers for the same networks.
- **`int-br-ex` has no tag.** It is a trunk, and OpenFlow rules on `br-int` and `br-ex` add and strip the external network's local VLAN.
- **`type: internal`** on `qr-`, `qg-` and the DHCP `tap` means they are OVS-created interfaces moved into a namespace, so they don't show up in `ip a` on the host.
- **`vxlan-0a07000c`**: one tunnel port per peer node. `in_key=flow` / `out_key=flow` means the VNI is chosen by flows, not by the port. The name suffix is the **remote** IP in hex:

  ```bash
  printf '%02x%02x%02x%02x\n' 10 7 0 12        # 0a07000c  (IP `->` hex)
  printf '%d.%d.%d.%d\n' 0x0a 0x07 0x00 0x0c   # 10.7.0.12 (hex `->` IP)
  # or: gethostip -x 10.7.0.12   (syslinux package)
  ```

  These ports are created when the OVS agent on the **other** node starts and registers its tunnel IP, not when a VM boots. A missing `vxlan-*` port for a node means that node's agent isn't registered, so check `openstack network agent list` and the `tunnel_sync` messages in its agent log.

- **`eth2g`**: the physical NIC attached to `br-ex`. It must be up and have **no IP address** of its own.

### Checklist, layer by layer

**1. Control plane** (agents alive, ports bound)

```bash
openstack network agent list                       # every agent Alive and UP
openstack port show <port-id> -c status -c binding_vif_type -c binding_host_id
podman ps --format '{{.Names}}\t{{.Status}}' | grep -E 'neutron|openvswitch'
tail -f /var/log/kolla/neutron/neutron-openvswitch-agent.log
tail -f /var/log/kolla/openvswitch/ovs-vswitchd.log
```

`binding_vif_type = binding_failed` means no live OVS agent on that host, or the network's physical network is not in its `bridge_mappings`.

**2. OVS bridges and ports**

```bash
ovs-vsctl show                                      # bridges, patch pairs, tags, controllers connected
ovs-vsctl list-ports br-tun                         # patch-int + one vxlan-<hex> per peer node
ovs-vsctl --columns=name,link_state,error list interface   # look for a non-empty "error"
ovs-ofctl show br-int                               # ofport numbers used in flows
```

**3. Underlay (tunnel network)**

```bash
ping -c3 -I 10.7.0.11 10.7.0.12                     # local_ip `->` remote_ip
ping -M do -s 1472 -c3 10.7.0.12                    # full 1500-byte underlay frame, no fragmentation
tcpdump -ni <tunnel-nic> udp port 4789 -c 10        # VXLAN traffic; tcpdump prints the vni
```

If the tunnel works for small packets but not large ones, it's an MTU problem. VXLAN adds 50 bytes, so a 1500-byte underlay gives tenants **1450**. Check `openstack network show <net> -c mtu` and test inside a VM with `ping -M do -s 1422 <peer>` (1422 + 28 = 1450).

**4. Flows**

```bash
ovs-ofctl dump-flows br-tun
ovs-ofctl dump-flows br-int
ovs-ofctl dump-flows br-ex
watch -d "podman exec openvswitch_vswitchd ovs-ofctl -O OpenFlow13 dump-flows br-tun | grep -v n_packets=0"
```

Watch the `n_packets` counters while you ping. A flow that matches but never counts is the wrong flow, and one that counts but doesn't forward points at the next hop.

Rough guide to `br-tun` tables (numbers can vary by release; dump the flows to confirm):

| Table | Role                                                                 |
| ----- | -------------------------------------------------------------------- |
| 0     | Dispatch by input port: `patch-int` vs each `vxlan-*`                |
| 4     | VXLAN: `tun_id` (VNI) `->` local VLAN (`mod_vlan_vid`)               |
| 10    | Learn the sender's MAC and tunnel from received packets              |
| 20    | Known destination MAC `->` local VLAN to VNI `->` specific `vxlan-*` |
| 21    | ARP responder (when `arp_responder = true`)                          |
| 22    | Unknown or broadcast `->` flood to every tunnel for that network     |

The VNI in the flows is in hex: `printf '%x\n' <vni>` converts a network's `segmentation_id` so you can `grep` for it.

For the external path, `br-int` has a rule that tags frames from `int-br-ex` with the external network's local VLAN, and `br-ex` has one that strips that tag on the way out:

```bash
ovs-ofctl dump-flows br-ex  | grep phy-br-ex
ovs-ofctl dump-flows br-int | grep int-br-ex
ovs-appctl fdb/show br-ex                           # is the upstream gateway MAC learned on the physical port?
ovs-appctl fdb/show br-int                          # MAC `->` local VLAN `->` port
```

Higher-numbered `br-int` tables (71 and up) hold the OVS firewall (security-group) flows.

**5. Namespaces (network node)**

```bash
ip netns exec qrouter-$R ip -br a
ip netns exec qrouter-$R ip r                       # default route via the external gateway?
ip netns exec qrouter-$R sysctl net.ipv4.ip_forward # must be 1
ip netns exec qrouter-$R iptables -t nat -S         # SNAT and floating-IP DNAT rules
ip netns exec qrouter-$R conntrack -L               # live NAT sessions (if conntrack is installed)
ip netns exec qdhcp-$N ip -br a
ip netns exec qdhcp-$N ss -lunp | grep ':67'        # dnsmasq listening for DHCP
ip netns exec qdhcp-$N ss -lntp | grep ':80'        # metadata proxy, if enabled
```

Reference output from the example above:

```text
qdhcp-e0cfefd4-46e9-4fd9-bca9-12b1f1c08e77 (id: 0)
```

- **`qg-992305b0-97`** (tag 2, `external-net`): the router's gateway port inside the router namespace. `10.7.0.167/24` is the router's own external IP (used for SNAT) and `10.7.0.131/32` is a **floating IP**, added as a `/32` on the same port.
- **`qr-6913bf48-bb`** (tag 1, `mgmt-net`): the router's interface on the tenant subnet. `10.128.0.1` is the default gateway VMs use.
- **`tap6f70784c-f7`** (tag 1, `mgmt-net`): the DHCP port inside `qdhcp-`, where `dnsmasq` serves DHCP to VMs on `mgmt-net` (`10.128.0.2`). The extra `169.254.169.254/32` means this namespace also answers **metadata** requests.

**6. Follow the packet.** Capture at each hop while pinging from a VM, and note the first hop where it stops:

```bash
# compute node
tcpdump -ni tap<port-suffix> icmp                   # 1. leaves the VM
tcpdump -ni <tunnel-nic> udp port 4789              # 2. encapsulated on the underlay

# network node
tcpdump -ni <tunnel-nic> udp port 4789              # 3. arrives encapsulated
ip netns exec qrouter-$R tcpdump -ni qr-<suffix> icmp   # 4. enters the router
ip netns exec qrouter-$R tcpdump -ni qg-<suffix>  icmp  # 5. leaves the router (after SNAT)
tcpdump -ni eth2g icmp                              # 6. on the wire; source is the qg / floating IP
```

To see what OVS will do with a frame without sending one:

```bash
ovs-appctl ofproto/trace br-int in_port=<ofport>,icmp,dl_src=<vm-mac>,dl_dst=<gw-mac>,nw_src=<vm-ip>,nw_dst=8.8.8.8
```

### Symptom `->` likely cause

| Symptom                                                    | Likely cause                                                                                                                 | Check                                                                                     |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Instance `ERROR`, port `binding_failed`                    | OVS agent down on that host, or physnet not in `bridge_mappings`                                                             | `openstack network agent list`, agent log, `bridge_mappings` in `openvswitch_agent.ini`   |
| VM gets no IP                                              | DHCP agent or `dnsmasq` not running, `qdhcp-` namespace missing, or no connectivity to the network node                      | `ip netns`, `tcpdump -ni tap… port 67 or port 68` inside `qdhcp-`, DHCP agent log         |
| VMs on the same host talk, across hosts don't              | Missing `vxlan-*` port, UDP 4789 blocked, `br-tun` flows missing                                                             | `ovs-vsctl list-ports br-tun`, `tcpdump udp port 4789`, controller `is_connected`         |
| Pings work, SSH or large transfers hang                    | MTU                                                                                                                          | `openstack network show -c mtu`, `ping -M do -s 1422` from the VM                         |
| VM reaches the gateway (`10.128.0.1`) but not the internet | No router gateway, no default route in `qrouter-`, `ip_forward=0`, NIC not in `br-ex`, upstream VLAN or switch port          | `ip netns exec qrouter-$R ip r`, `ovs-vsctl list-ports br-ex`, `tcpdump -ni eth2g`        |
| Router gateway IP (`qg`) not pingable from outside         | `qg` port down, wrong `bridge_mappings`, missing `phy-br-ex` flows, upstream ARP problem, libvirt `nwfilter` on a nested NIC | `ovs-appctl fdb/show br-ex`, `dump-flows br-ex`, `tcpdump -ni eth2g arp`                  |
| Instance reaches the internet, floating IP unreachable     | DNAT/SNAT rule missing, security group blocks ICMP/SSH, `/32` missing on `qg`                                                | `iptables -t nat -S` in `qrouter-`, `ip -br a` on `qg`, security-group rules              |
| cloud-init fails to reach `169.254.169.254`                | Metadata proxy not running in `qrouter-`/`qdhcp-`, or no route to it                                                         | `curl` from the VM, `ss -lntp` in the namespace, metadata agent log                       |
| `is_connected: false` on a controller                      | OVS agent stopped or hung                                                                                                    | `podman restart neutron_openvswitch_agent`, read its log                                  |
| Everything dead after an OVS or node restart               | `secure` bridges have no flows until the agent reprograms them                                                               | Wait for the agent, then `dump-flows`; restart the agent if the flow count stays tiny     |
| Extra `vxlan-*` ports for nodes that no longer exist       | Stale tunnel endpoints                                                                                                       | `openstack network agent list`, delete the dead agent, `ovs-vsctl del-port br-tun <port>` |

Isolate security groups by temporarily removing them from the port. This is a test only, so restore them afterwards:

```bash
openstack port set <port-id> --no-security-group --disable-port-security
openstack port set <port-id> --enable-port-security --security-group default
```
